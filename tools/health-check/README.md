# 自作プラグイン健康診断

入っている自作プラグイン（`~/Library/Audio/Plug-Ins/Components` にあるメーカー MyPlugins の AU）を 1 つずつ読み込みます。
試験の音を通して、音の処理がおかしくなっていないかを数値で調べる道具です。
Logic も画面も使いません（自前の小さなホストで、裏で動かします）。マウスも取りません。

## いつ動くか
- Claude アプリの定期実行「【毎晩】自作プラグイン健康診断」が、毎晩 3 時ごろに動かします
- Claude アプリが開いている間だけ動きます。寝ている間に Mac がスリープしていたら、次に起こしたときに動きます
- 検査そのものは 30〜60 分くらいです。その後、Claude が引っかかった所のコードを読んで「本当に不具合か・仕様か」を判断し、報告を書きます
- 終わると Mac に通知が出ます。報告は、Claude アプリのその回の会話と `build/health/reports/<日付>.md` に残ります

## 何を調べるか
| 検査 | 中身 | Logic で困ること |
|---|---|---|
| 基本 | 読み込み時間、無音を入れたときの雑音、音楽を通したときの NaN（壊れた数）・ピーク・音量の差・DC（0 からのずれ）・CPU、遅れの申告が正しいか、止めた後に鳴り止むか、リセットで前の音が消えるか | 音割れ、ノイズ、重さ、位置ずれ、鳴りっぱなし |
| プチノイズ | つまみを 1 つずつ急に動かして、プチッと鳴らないか | オートメーションや手で回したときのノイズ |
| ランダム設定 | つまみをランダムに 12 通り（ほどほど 6 通り・端まで 6 通り）入れて、発振・音割れ・NaN が出ないか | 変な設定で音が壊れる・爆音 |
| 保存 | 設定を保存して開き直したとき、つまみと音が同じか | 曲を開き直すと音が変わる |
| ブロックの大きさ | 一度に処理する量（1〜4096 サンプル）を変えても同じ音か | バッファの設定や書き出しで音が変わる |
| サンプルレート | 44.1 / 48 / 96 / 192 kHz で同じように動くか | 曲の設定によって音が変わる・壊れる |
| モノラル | モノラルのトラック（1→1、1→2）で動くか | モノのトラックで落ちる・片側だけ鳴る |
| GAIN MATCH | ON にしたら音量がそろうか | 聴き比べがずれる |
| auval | Apple の検査 | Logic に読み込まれない |
| 入っている版 | リポジトリの版と同じか、消したプラグインが残っていないか | 古い版のまま使っている |

## 結果の読み方
- **異常** … ほぼ確実におかしい（NaN、落ちる、保存されない、遅れの申告違いなど）
- **注意** … おかしいかもしれない。仕様のこともあるので、Claude がコードを見て判断します
- **参考** … 仕様のことが多いもの（足すノイズ、ランダムな揺れ、切り替えのプチッなど）
- 仕様だと決めたものは `KNOWN.md` に書いておくと、次の夜から報告の最後に件数だけ出ます

## 手で動かすとき（~/plugins で）
```
bash tools/health-check/nightly.sh
bash tools/health-check/nightly.sh --only Ecdr,Mytr
build/health/hc list
build/health/hc params Ecdr
build/health/hc run Ecdr click /tmp/x.json
```
- `--only` にはコード（Ecdr）かフォルダ名（EchoDrift）、`--groups` には basic,click,random,state,block,rates,mono,gainmatch
- ランダム設定は日付で毎晩違う組み合わせになります。同じ組み合わせを再現するには `--seed <番号>` と `--set <0〜11>`（番号は報告の数値の中にあります）

## 直すとき
報告で「直したほうがいいもの」に番号が付きます。Claude に「健康診断の 1 を直して」と言えば、いつもの決まり（DSP 検査係のチェック → push → ビルド → インストール）で直します。
報告の時点では、コードは何も変えていません。
