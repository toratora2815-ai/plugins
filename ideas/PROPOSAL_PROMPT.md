# 提案の作り方（Claude 用の指示書）

余っている利用枠を使って、「次に作るべきもの・直すべきもの」を Claude が自分で考えて提案するための指示です。
クラウドの定期実行と、Mac の残量チェック（tools/usage-watch）の両方がこのファイルを読みます。
**提案するだけで、コードはまだ一切変えない。** 本人が「GO」と言ってから作る。

## 1. 調べる
- `CLAUDE.md`（作ったもの一覧と技術の決まり）
- `MyPlugins/*/README.md`（各プラグインのつまみと現状）
- `git log --oneline -30`（最近なにをやったか）
- `ideas/proposals/` の過去の提案（同じ提案をくり返さない。GO されていない良い案を練り直して出すのは OK）
- 必要なら各プラグインの `Source/` を読んで、具体的な弱点（重い処理、足りない機能、使いにくい UI、テスト不足など）を探す

## 2. 3つ提案する
- 少なくとも1つは「いまあるプラグイン／アプリの改善」、少なくとも1つは「新しいプラグイン／アプリ」
- 使う人は Mac + Logic Pro で曲を作っている。ミックスや音作りで本当に助かるものを優先
- 実在製品の名前・見た目はまねしない（音のキャラクターの参考はOK）。AU だけ
- それぞれ次の形で書く:

```
### 1. <タイトル>
- 種類: 改善（<プラグイン名>） / 新規
- できるようになること: <音楽的に、何がどう良くなるか。2〜3行>
- なぜ今: <理由>
- 中身: <主な機能・つまみ。箇条書き3〜6個>
- 大きさ: 小（1回の会話で終わる） / 中 / 大（数回に分ける）
- 気をつける点: <リスクや、作る前に決めたいこと>
```

## 3. 残す・知らせる
- 最後の一文は必ず「やりたい番号を『GO 2』のように返信してね（複数なら『GO 1 3』）。いらなければ放置でOK」
- クラウドで動いているとき: 提案を `ideas/proposals/YYYY-MM-DD-HHMM.md`（日本時間）に保存し、
  `git config user.name Claude` / `git config user.email noreply@anthropic.com` で commit して main に push する
  （ビルドは走らない）。最後の返事にも3つの提案の要約（タイトル＋1行）を書く
- Mac の残量チェックから動いているとき: ファイルは書かず、提案の本文をそのまま出力する（スクリプトが保存する）
